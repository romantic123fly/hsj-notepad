> 版本：v1.0
> 文档状态：已定稿（供 UI 设计与前端开发落地）
> 作者：需求规划（planner）

## 1. 产品概述与目标用户

### 1.1 产品概述

本产品是一个**纯前端、无后端**的网页端幻世界临时文本记录工具（记事本），通过浏览器打开 `index.html` 即可运行（支持双击运行）。核心能力包含两部分：

1. **记事本**：记录临时文本，支持新建、编辑、保存；视图左侧「切换目录」列出全部笔记，支持点击打开/切换、删除、清空。
2. **Markdown → Word 转换**：输入/粘贴 Markdown，一键转换为 Word（`.doc`）并下载；同时可在页面内直接预览转换结果（渲染后的 HTML）。

产品定位：**开箱即用、零依赖部署、本地持久化的轻量工具**。不依赖任何服务器、数据库或登录体系，数据完全保存在用户本机浏览器中。

### 1.2 目标用户

| 用户角色 | 典型场景 | 核心诉求 |
| --- | --- | --- |
| 普通办公/文字工作者 | 随手记录临时信息、草稿、待办，快速整理成 Word 文档 | 快速记录、简单易用、本地保存不丢 |
| 开发/技术写作者 | 用 Markdown 撰写说明、文档、笔记，需要导出 Word 交付 | Markdown 转 Word、所见即所得的预览 |
| 学生/研究者 | 记录笔记、资料摘录，整理后导出为文档 | 历史可追溯、可切换、可清空 |
| 对隐私敏感的用户 | 不希望数据上传云端 | 数据仅存本机（localStorage） |

### 1.3 产品目标

- **零门槛**：双击 `index.html` 即可使用，无需安装、无需联网、无需配置。
- **本地安全**：所有数据仅存于浏览器 localStorage，不产生任何网络请求（除本地引入的第三方库）。
- **高效**：核心操作（新建、保存、切换、转换、下载）均在一屏内完成，交互路径短。

### 1.4 非目标（明确不做）

- 不做用户登录、多端同步、云存储。
- 不做多人协作、实时共享。
- 不做富文本（所见即所得）编辑器；记事本保持纯文本，Markdown 模块用源码编辑 + HTML 预览。
- 不做 Markdown 的 `.md` 文件下载（当前仅支持转 Word；如后续需要可作为扩展）。

## 2. 功能需求

### 2.0 全局信息架构与页面结构

单页应用（SPA），页面采用 **标签页（Tab）** 切换两个模块，默认进入「记事本」模块。

- **顶部**：应用标题 + 两模块导航（记事本 / Markdown 转 Word）。
- **主体**：根据当前模块渲染对应视图；「记事本」视图内分为左侧「切换目录」（笔记列表）与右侧编辑区。
- 所有模块共享同一份 localStorage 数据源（见第 3 章数据模型）。

> 说明：具体视觉呈现由 UI 设计负责；本 PRD 只约束信息架构与交互行为。

### 2.1 模块一：记事本（Notes）

#### 2.1.1 功能点

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| N-01 | 新建 | 清空当前编辑区，进入空白笔记编辑态；标题可留空（见 N-02） |
| N-02 | 编辑 | 提供「标题输入框」+「正文文本域（textarea）」两处可编辑区域；标题允许为空 |
| N-03 | 保存 | 将当前标题 + 正文保存为一个笔记快照（新增或更新，规则见 N-04/N-05） |
| N-04 | 自动保存（可选增强） | 编辑暂停 N 秒（默认 3 秒）后自动保存草稿，避免误关丢失（见 5.1 非功能） |
| N-05 | 保存/更新策略 | 同一会话内对「当前笔记」的反复保存视为**更新**而非新增；切换「新建」后再次保存才产生新笔记 |
| N-06 | 保存反馈 | 保存成功给出轻提示（toast/状态文字），并显示当前保存时间 |

#### 2.1.2 交互流程

```
[进入记事本模块]
      │
      ├─ 首次打开（无当前笔记）→ 显示空白编辑器，标题/正文均空
      │
      ├─ 用户输入标题 + 正文
      │        │
      │        └─ 点击「保存」→ 校验 → 生成笔记快照 → 写入 localStorage
      │                               └─ 成功 → toast 提示 + 记录保存时间
      │                               └─ 失败（容量满等）→ 错误提示（见 3.4）
      │
      ├─ 点击「新建」→ 确认是否放弃未保存内容（如有）→ 清空编辑器
      │
      └─ 从左侧「切换目录」点击某条笔记 → 打开/切换该笔记到编辑器（见 2.2）
```

**关键规则：**
- 「新建」前若当前编辑区有未保存内容，需弹出确认提示：「当前内容尚未保存，确定放弃吗？」（防误触丢失）。
- 「当前笔记」概念：应用内存中维护一个「正在编辑的快照 ID」（`currentNoteId`）。若为空，则「保存」为新增；若非空，则「保存」为更新该快照。点击「新建」或「切换其他笔记」会重置/切换该 ID。

### 2.2 记事本视图内左侧「切换目录」（笔记列表）

原「历史记录」不再作为独立模块，改为「记事本」视图内的左侧「切换目录」（笔记列表），替代原「查看 / 恢复」交互。

#### 2.2.1 功能点

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| D-01 | 列表展示 | 按「保存时间倒序」展示所有笔记：标题（无标题则显示正文前 N 字或「无标题」）+ 保存时间 + 正文摘要 |
| D-02 | 打开/切换 | 点击某条笔记，将其加载为「当前笔记」并在右侧编辑区打开（替代原「查看 / 恢复」）；切换前若有未保存内容需二次确认 |
| D-03 | 删除（单条） | 删除某一条笔记，需二次确认 |
| D-04 | 清空（全部） | 一键清空全部笔记，需二次确认（输入式确认或强提醒） |
| D-05 | 新建 | 点击「新建」清空编辑区，进入空白笔记编辑态（与 2.1 的 N-01 一致） |
| D-06 | 空状态 | 无任何笔记时展示空状态提示（引导用户新建第一条） |
| D-07 | 时间显示 | 保存时间本地化显示（如 `YYYY-MM-DD HH:mm:ss`） |

#### 2.2.2 交互流程

```
[记事本视图内左侧「切换目录」]
      │
      ├─ 无数据 → 空状态提示
      │
      ├─ 有数据 → 列表（倒序）
      │        ├─ 点击某条笔记「打开/切换」→ 加载为当前笔记到右侧编辑区（切换前确认未保存内容）
      │        ├─ 点击「删除」→ 二次确认 → 删除该条 + 刷新列表
      │        ├─ 点击「新建」→ 确认未保存内容 → 清空编辑区
      │        └─ 点击「清空全部」→ 强确认 → 清空 + 刷新为空状态
      │
      └─ 删除/清空后列表实时刷新
```

**关键规则：**
- 打开某条笔记后，该笔记成为「当前笔记」，编辑再保存视为**更新**该笔记（见 2.1 的 N-05），列表标题/内容/时间同步刷新。
- 清空操作为破坏性操作，建议使用「输入 `DELETE` / 勾选确认」等强确认方式。

### 2.3 模块二：Markdown → Word 转换（Convert）

#### 2.3.1 功能点

| 编号 | 功能 | 描述 |
| --- | --- | --- |
| C-01 | 输入 | 提供 Markdown 源码编辑区（textarea）供输入/粘贴 |
| C-02 | 转换（预览） | 将 Markdown 通过 `marked` 渲染为 HTML，并在「预览区」在线展示转换结果（实时或点击「预览」按钮触发，见 2.3.2） |
| C-03 | 导出 Word | 将渲染后的 HTML 封装为 `.doc`（HTML 内容 + Word 命名空间头，保存为 `.doc` 由 Word 打开的 MHTML 方式，见 2.3.3）并触发浏览器下载 |
| C-04 | 清空 | 一键清空输入区与预览区 |
| C-05 | 示例加载（可选） | 提供一段示例 Markdown，便于用户快速体验 |
| C-06 | 预览模式说明 | 预览即为「渲染后 HTML 的在线查看结果」；是否引入 `docx-preview` 做真实 Word 渲染预览需论证（见 2.3.4） |
| C-07 | 布局/纸张样式 | 源码区与预览区加宽到 A4 纸张宽度（约 794px），预览区为白色纸张样式，模拟 Word 纸张观感 |

#### 2.3.2 交互流程

```
[进入 Markdown 转 Word 模块]
      │
      ├─ 用户输入/粘贴 Markdown 到源码编辑区
      │        │
      │        ├─ 实时预览模式：输入即触发 marked 渲染 → 预览区更新
      │        └─ 手动预览模式：点击「预览」→ 渲染 → 预览区更新
      │
      ├─ 点击「导出 Word」→ 渲染 HTML → 封装 .doc → 触发下载
      │
      └─ 点击「清空」→ 清空输入 + 预览
```

#### 2.3.3 导出实现方案（技术约束落地）

纯前端生成 Word 文档的可行方案（供开发选择，PRD 推荐方案 A）：

| 方案 | 原理 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A（推荐）** | `marked` 渲染 MD→HTML，再将 HTML 包装为 Word 可打开的 MHTML 文档（`.doc` 后缀），利用 `Blob` 触发下载 | 无需额外库；Word/WPS 均能打开；样式可控 | 本质是「HTML 伪装 Word」，非严格 OOXML；复杂排版（分页、页眉页脚）不支持 | **采用** |
| B | 引入 `html-docx-js`（`htmlToDocx`）生成真正的 OOXML `.docx` | 生成的是标准 docx | 依赖较重；对部分 HTML/CSS 支持有限；需处理图片/样式 | 备选，如方案 A 不满足再引入 |
| C | 引入 `docx`（JS 库）逐段构建 | 结构精确可控 | 需逐元素映射 Markdown 节点，工作量大 | 不推荐（投入产出比低） |

> 推荐采用**方案 A**：纯前端、零额外依赖、可离线运行，符合「打开 index.html 即可运行」的硬约束。

**导出实现要点：**
1. 用 `marked` 将 Markdown 解析为 HTML 字符串（建议启用 `breaks`、`gfm` 等选项以获得更好的换行/表格支持）。
2. 将 HTML 包进一段 Word 兼容的 MHTML 文档模板（含 `xmlns:w`、`xmlns:o` 等命名空间，`<w:WordDocument>` 头 + `<body>` 内的 HTML）。
3. 通过 `Blob` + `URL.createObjectURL` 触发 `<a download="文件名.doc">` 下载。
4. 文件名建议：默认 `文档_YYYYMMDD_HHmmss.doc` 或使用 Markdown 首行标题。

#### 2.3.4 是否引入 `docx-preview` 的论证

| 维度 | 方案 A 的 HTML 预览（marked 渲染） | `docx-preview`（渲染真实 .docx） |
| --- | --- | --- |
| 技术链路 | Markdown→HTML→直接显示 | 需先 Markdown→docx 二进制→再反渲染回 HTML/Canvas |
| 依赖体积 | 无额外依赖 | 需引入 `docx-preview` + `jszip` 等，体积较大 |
| 离线可用 | ✅ 完全离线 | ⚠️ 需本地打包依赖（离线可用但增加复杂度） |
| 预览还原度 | 即「转换结果」的 HTML 展示，足够作为转换结果预览 | 是「导出后 Word 的真实效果」预览，更接近最终交付 |
| 复杂度/风险 | 低 | 中高，且与方案 A（MHTML 导出）链路不一致 |

**结论：** 本版本（v1.0）**不引入 `docx-preview`**，预览采用 `marked` 渲染后的 HTML（即方案 A 的「在线查看转换结果」）。理由：
1. 满足 PRD 所述「预览用渲染后的 HTML 作为在线查看转换结果」的原始定义；
2. 保持零额外依赖、可离线、体积小，符合技术约束；
3. 方案 A 的导出本质就是「渲染后 HTML → Word」，HTML 预览与导出内容一致，预览已足够可信。

> 预留扩展：若后续需要「所见即最终 Word 排版」的严格预览，再评估引入 `docx-preview` + 改用方案 B/C 生成真实 docx。该决策点记录为**开放项**，不阻塞 v1.0。

## 3. 数据模型

### 3.1 笔记对象字段（Note）

```jsonc
{
  "id": "string",           // 唯一标识，如时间戳+随机数：`Date.now() + '-' + Math.random().toString(36).slice(2, 8)`
  "title": "string",        // 笔记标题，允许为空字符串
  "content": "string",      // 笔记正文（纯文本，允许换行）
  "createdAt": 1731900000000, // 首次创建时间戳（毫秒，number）
  "updatedAt": 1731900000000  // 最后保存/更新时间戳（毫秒，number）
}
```

### 3.2 存储键（localStorage Key）

| 键名 | 值类型 | 说明 |
| --- | --- | --- |
| `notes.app.notes` | JSON 字符串（数组） | 全部笔记快照列表，元素为 Note 对象，按 `updatedAt` 倒序或插入序存储 |
| `notes.app.currentNoteId` | string \| null | 当前正在编辑的快照 ID；为 `null`/空 表示「新建态」，保存即为新增 |
| `notes.app.settings` | JSON 对象 | 应用设置（预留：如自动保存开关、主题等，v1.0 可最小化） |

> 建议：为避免与其他站点/应用 key 冲突，统一使用 `notes.app.*` 前缀。

**数据结构示例（`notes.app.notes`）：**

```json
[
  {
    "id": "1731900000123-abc12",
    "title": "会议纪要",
    "content": "第一行内容\n第二行内容",
    "createdAt": 1731900000123,
    "updatedAt": 1731900123456
  }
]
```

### 3.3 数据读写策略

- **读**：应用启动时从 localStorage 读取 `notes.app.notes`（解析失败则按空数组兜底）与 `notes.app.currentNoteId`。
- **写**：每次保存/删除/清空后，将最新数组整体 `JSON.stringify` 写回 localStorage（数据量小，整体覆写简单可靠，无需增量）。
- **原子性兜底**：写入用 `try/catch` 包裹，捕获 `QuotaExceededError`（容量满）等异常并给出用户提示。

### 3.4 容量与清理策略

- localStorage 典型单源上限约 **5MB**（不同浏览器略有差异，UTF-16 计数）。纯文本笔记容量充足，单条建议限制在合理范围内（见下）。
- **单条限制**：标题 ≤ 200 字符；正文 ≤ 200,000 字符（约可容纳长篇文档，超出提示「内容过长」）。
- **总容量保护**：写入前估算 `JSON.stringify(data).length`；若接近/超过上限，提示用户「存储空间不足，请删除部分历史记录」，并拒绝保存（不静默失败）。
- **清理策略**：由用户手动清理（删除单条/清空全部）；不提供自动清理（避免误删用户数据）。可选：在历史模块顶部显示「已用存储估算」，帮助用户感知容量。

### 3.5 隐私与安全

- 数据仅存本机浏览器，不发起任何网络请求（第三方库建议本地化引入，避免 CDN 联网依赖，保证离线可用）。
- 清理浏览器数据（清除站点数据）会导致笔记丢失，此为 localStorage 方案固有特性，不纳入产品保障范围（可在界面提示「数据仅保存在本机」）。

## 4. 非功能需求

### 4.1 性能

- 首屏加载：本地静态资源，冷启动（含第三方库）在常见带宽/本地下应在 1s 内可交互。
- 交互响应：保存、切换模块、列表渲染等操作 < 100ms（数据量 < 1000 条）；历史列表超过一定条数（如 500 条）建议做分页或懒加载，避免一次性渲染卡顿。
- Markdown 渲染：常规文档（< 1 万字符）`marked` 渲染 < 50ms；长文档需防抖（debounce）后再触发实时预览，避免频繁渲染。

### 4.2 浏览器兼容

- 支持现代主流浏览器最新两个大版本：Chrome、Edge、Firefox、Safari。
- 依赖能力：`localStorage`、`Blob`、`URL.createObjectURL`、`<a download>`，均为现代浏览器原生支持；无需 polyfill。
- 目标运行方式：桌面浏览器双击 `index.html`（`file://` 协议）下完整可用（**特别注意**：第三方库需本地文件引入，避免 `file://` 下 ES Module / CDN 跨域加载失败）。

### 4.3 离线可用

- 全程离线可用：所有资源本地化，不依赖网络；无任何外部请求。
- 无 Service Worker / PWA 要求（可选，不作为 v1.0 验收项）。

### 4.4 响应式与可访问性

- 响应式：桌面优先，适配常见窗口（≥ 1024px 最佳）；窄屏（平板/手机）下两个模块改为纵向排列、可堆叠布局，编辑区与预览区上下排布。
- 可访问性：表单元素含 `label`、按钮可键盘操作（Tab 聚焦）、关键操作有明确反馈（成功/失败提示）、破坏性操作有二次确认。
- 键盘快捷键（可选增强）：`Ctrl+S` 保存、`Ctrl+N` 新建（需拦截浏览器默认行为）。

### 4.5 健壮性与容错

- localStorage 数据损坏/解析失败时，以空数组兜底启动，不崩溃，并提示「本地数据异常」。
- 容量满（QuotaExceededError）时给出明确提示，不静默失败。
- 导出 Word 失败（如 Blob 异常）时给出提示。

## 5. 验收标准（可测试 Checklist）

> 每条均为可人工点验的测试项，全部通过视为验收通过。

### 5.1 通用 / 启动

- [ ] 双击 `index.html`（`file://` 协议）可正常打开，两个模块导航（记事本 / Markdown 转 Word）可见，默认进入「记事本」。
- [ ] 无网络环境下打开，页面功能完整可用（无因 CDN 缺失而报错）。
- [ ] 刷新页面后，已保存的笔记仍在（持久化生效）。

### 5.2 记事本

## 6. 模块拆分与文件结构建议

### 6.1 技术选型（已由 Lead 定案，此处固化）

- 原生 HTML / CSS / JavaScript（ES 模块化或普通 `<script>` 均可，建议普通脚本 + 全局命名空间或 IIFE，以兼容 `file://` 直接打开）。
- 无前端框架、无构建工具（保证双击可运行）。
- 持久化：`localStorage`。
- MD→HTML：`marked`（本地引入 `marked.min.js`）。
- 导出 Word：方案 A（HTML 封装为 MHTML 的 `.doc`，用 Blob 下载）。

### 6.2 文件结构建议

```
3b894b31/                        ← 项目根目录（可直接打包分发）
├── index.html                   ← 入口页面（双击打开）
├── assets/
│   └── lib/                     ← 第三方库（本地化，保证离线）
│       └── marked.min.js        ← MD→HTML 解析库
├── css/
│   └── style.css                ← 全局样式（含响应式）
├── js/
│   ├── app.js                   ← 应用入口：模块路由/导航、启动初始化
│   ├── storage.js               ← localStorage 封装：读写、容量检查、异常兜底
│   ├── notes.js                 ← 记事本模块逻辑
│   ├── history.js               ← 记事本左侧切换目录（笔记列表）逻辑
│   ├── converter.js             ← Markdown→HTML→Word 转换与下载
│   └── ui.js                    ← 通用 UI 辅助：toast 提示、确认弹窗、时间格式化
└── docs/
    └── requirements.md          ← 本文档（PRD）
```

### 6.3 模块职责与依赖关系

| 模块 | 文件 | 职责 | 依赖 |
| --- | --- | --- | --- |
| 入口 | `js/app.js` | 初始化、两模块 Tab 切换、启动时加载数据 | `storage.js`、各模块 |
| 存储层 | `js/storage.js` | 读写笔记、当前笔记 ID、设置；容量/异常处理 | 无（底层） |
| 记事本 | `js/notes.js` | 编辑、新建、保存（新增/更新）、保存反馈 | `storage.js`、`ui.js` |
| 切换目录 | `js/history.js` | 笔记列表：打开/切换、删除、清空、新建、空状态 | `storage.js`、`notes.js`、`ui.js` |
| 转换 | `js/converter.js` | marked 渲染、预览更新、Word 导出下载、清空 | `marked`（lib）、`ui.js` |
| UI 工具 | `js/ui.js` | toast、确认弹窗、日期格式化、容量估算展示 | 无 |

**依赖原则：** 单向依赖（上层模块 → `storage.js` / `ui.js`），`storage.js` 与 `ui.js` 为无业务依赖的底层；`notes.js` 与 `history.js` 之间通过 `storage.js` 交换数据，避免循环依赖。

### 6.4 关键实现约定（供开发直接落地）

1. **命名空间**：为避免全局污染，建议用 IIFE 模块模式，通过 `window.NotesApp = { app, storage, notes, history, converter, ui }` 暴露统一入口。
2. **数据唯一出口**：所有 localStorage 读写都必须经过 `storage.js`，业务模块不得直接 `localStorage.setItem`。
3. **时间戳**：统一使用 `Date.now()`（毫秒 number），展示时由 `ui.formatTime()` 转为 `YYYY-MM-DD HH:mm:ss`。
4. **ID 生成**：`Date.now() + '-' + Math.random().toString(36).slice(2, 8)`，保证足够唯一性。
5. **事件绑定**：DOM 元素加载完成后绑定事件（`DOMContentLoaded` 或脚本置于 `</body>` 前）。
